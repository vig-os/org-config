# [PR 287](https://github.com/vig-os/org-config/pull/287) docs(secrets): record why the App Client ID stays a secret

## Description

Implements the decision issue [#270](https://github.com/vig-os/org-config/issues/270) was blocked
on and writes it down. `ORG_CONFIG_APP_CLIENT_ID` is held as a bootstrap **Actions secret**, but
`GET https://api.github.com/apps/vig-os-org-config` answers **200 to an anonymous caller** and
returns `client_id` plus the full 17-permission grant (re-probed 2026-09-28) — so the value was
never confidential, and nothing in the repo said so.

**Decision (2026-09-28): Option A — it stays an Actions secret.** The secret buys **uniformity, not
confidentiality**: every consumer hands the Client ID to `actions/create-github-app-token` in the
same breath as the PEM (`client-id:` beside `private-key:`), and the three sibling
`*_APP_CLIENT_ID` **org** secrets ([#112](https://github.com/vig-os/org-config/issues/112)) are
declared the same way, so a variable here would make this App the exception. The alternative's cost
is the **cutover, not the edit**: an engine reading `vars.ORG_CONFIG_APP_CLIENT_ID` while a
downstream caller still passes `secrets.ORG_CONFIG_APP_CLIENT_ID` does not fail loudly — an
undefined `vars.` reference resolves to the **empty string**, i.e. a silent empty credential,
failing late in the token step or, on the scheduled `drift` leg, in a run nobody is watching. That
is only safe inside a coordinated pin bump.

The operationally important half is the second acceptance item: the repo now states that a
**disclosed Client ID is not a rotation trigger** (the PEM is). `grep -rn "rotation trigger"`
returned nothing before this change, and **Key rotation** said only that the Client ID *does not
change* — leaving a reader who finds the value published free to conclude a key rotation is due.

Documentation only. No workflow, `template/`, jsonnet, ADR or secret value is touched, and Option B
(variable) is explicitly out of scope.

## Changes Made

- `docs/runbooks/github-app.md` (+55/-1), all of it inside the **Bootstrap secrets** and **Key
  rotation** sections:
  - beside the bootstrap secrets table: only one of the two entries is confidential. The Client ID
    is an *identifier*, not a credential (it mints no token without the key that signs the JWT); the
    anonymous `200` is recorded with its probe date; finding the value in a log, a screenshot, a
    public repo or a stranger's `curl` is **not an incident and starts no rotation**. Scoped
    **fleet-wide** to the three sibling `*_APP_CLIENT_ID` org secrets
    (`otterdog/vig-os/vig-os.jsonnet:66`, `:124`, `:189`), whose Apps `commit-action-bot`,
    `vigos-devkit-upgrade` and `vig-os-release-app` each answer `200` to the same anonymous call
    (probed 2026-09-28), so the next reader does not re-derive it per App. What stays per App is the
    paired private key, each its own rotation trigger.
  - the **Decision (2026-09-28, #270)** paragraph, in the voice the #261 visibility decision uses:
    it stays a secret knowingly, with the uniformity reason and the silent-empty-credential reason.
  - a four-step sequence for a future migration to a variable, framed as a coordinated pin bump and
    never a one-sided flip: both forms accepted in the engine first (`plan.yml:150`/`:229`,
    `apply.yml:165`/`:390`/`:499`, `drift.yml:131`/`:222`/`:316`, `apply-engine.yml:118`/`:142`,
    `testbed-e2e.yml:162`/`:172`) → the jsonnet declaration at `:625` moved from `secrets:` to
    `variables:`, where otterdog would genuinely assert it instead of the dummy `'********'` row →
    `template/README.md:101` and the four `template/.github/workflows/*.yml` callers plus
    `exo-pet`'s org-config caller cut over at a pin bump → only then the shim retired.
  - **Key rotation**'s opening paragraph, which said only that the Client ID does not change, now
    also says a *disclosed* Client ID is not a trigger for the procedure at all.
- `CHANGELOG.md`: one bullet under `### Changed` (see below).

Deliberately **not** changed: `.github/workflows/*`, `template/*`, `otterdog/vig-os/vig-os.jsonnet`,
ADR-0004, and the live secret. Also not touched: the **Visibility** section's sentence saying
"whether it stays a secret or becomes a variable is #270", which sits at `:240-245` — the exact
hunk [#286](https://github.com/vig-os/org-config/pull/286) is editing. It still resolves correctly
(the issue carries the decision); re-pointing it at this section is a one-line follow-up better done
after #286 lands than as a guaranteed conflict here.

public, the PEM is still a secret, and no storage changed.
