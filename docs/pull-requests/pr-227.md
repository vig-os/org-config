# [PR 227](https://github.com/vig-os/org-config/pull/227) chore(config): adopt tessera's `dev` default branch

## Description

Adopts `tessera`'s live default branch (`dev`) into the committed config, resolving the drift reported daily since 2026-09-08 in #215.

The repo block declared no `default_branch`, so it inherited the vendored `main` (`otterdog-defaults.libsonnet:24`) and the plan read `~ default_branch = "dev" -> "main"` — i.e. otterdog wanted to flip the live repo back.

The live value is the correct one, and the divergence is config lagging a documented decision, not an incident:

- [tessera#383](https://github.com/vig-os/tessera/pull/383) — *"docs(main): point the default branch to dev until the first alpha"* — states it in `main`'s own README: `main` is release-only with no release cut yet (`0.1.0-alpha.1` is held).
- `dev` is **516 commits ahead / 1 behind** `main`; `main`'s last substantive commit predating that README is 2026-06-30.
- All 5 open PRs, 29 of the last 30 merged PRs, and every Dependabot branch target `dev`.

Reverting would have pointed fresh clones and default PR bases at a branch stale since June, and would have undone a maintainer decision out from under them — the exact call [ADR-0002](docs/adr/0002-drift-semantics.md) puts in front of a human instead of automating.

Adopted in config rather than silenced in `drift-allowlist.toml`: `default_branch` is a first-class otterdog field, and the allow-list is for divergence the schema *cannot* express. `tessera` is the only vig-os repo off `main` (the other nine all are), so the deviation is declared explicitly and carries its expiry — *until the first alpha* — as a comment, keeping the eventual flip back a one-line change rather than a re-investigation.
