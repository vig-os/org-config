# [PR 310](https://github.com/vig-os/org-config/pull/310) chore(config): make Renovate the vulnerability-fix channel, Dependabot security updates off except qx

## Description

Takes the **Prefer Renovate** option of #307 now, instead of waiting for the 2026-10-29 watch to end.

Dependabot security-update PRs always target the default branch and ignore `target-branch`. On devkit-managed repos they fail the managed `Commit Messages` gate: the `dependabot/*` branch name is not allowed, and the titles are not Conventional Commits. vig-os/devkit-smoke-test#433, #434, #435, #436, #437 and vig-os/h5v#11 are all blocked on `Commit Messages` / `CI Summary`. From now on Renovate is the vulnerability-fix channel. **Dependabot alerts stay on everywhere.**

## Changes Made

Two commits, in the same order as #304:

1. `docs(adr)`: ADR-0008.
   - The "Dependabot security updates" bullet under Repository settings now says they are off. Every repo takes the vendored default (`false`) except `qx`. Vulnerability fix PRs come from Renovate, which targets each repo's integration branch, and alerts stay on everywhere. New repos default to off (`unmanaged-controls.toml`). The bullet is marked **Decided (2026-09-29, #307)** and replaces the tier-A opt-in made earlier the same day.
   - Two new Exceptions rows:
     - `qx` keeps security updates on because it has no Renovate yet. Exit: `qx` adopts Renovate and it is proven to run.
     - A known gap on `h5v`, `scitadel`, `tessera` and `devkit-smoke-test`. Advisories in ecosystems Renovate does not yet cover (Cargo, and `uv` on smoke-test) get alerts but no fix PR. Renovate is not running on `h5v`, `scitadel` or `tessera` at all. Exit: the per-repo Renovate coverage PRs land and Renovate is verified running.
   - A Corrections entry quotes the original "only where a required aggregator checks them" assumption and cites the blocked PRs.
2. `chore(config)`:
   - `otterdog/vig-os/vig-os.jsonnet`: the `dependabot_security_updates_enabled: true` line is deleted from the eight devkit-managed repos, so they inherit the vendored default `false`. This is the same approach as the #294 secret-scanning cleanup. `qx` keeps `true` and gets the comment `// ADR-0008 exception: no Renovate yet; Dependabot is its only fix-PR source.`
   - `unmanaged-controls.toml`: `new-repo-dependabot-security-updates` now expects `false`, with a matching title and reason.
   - `CHANGELOG.md`: a new `### Security` entry.

`template/**` is untouched. `template/otterdog/YOUR_ORG/house-defaults.libsonnet` is still byte-identical to the live copy (`cmp` exit 0), and `template/unmanaged-controls.toml` has no such control.
