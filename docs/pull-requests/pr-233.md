# [PR 233](https://github.com/vig-os/org-config/pull/233) docs(just): note that editing the otterdog pin now triggers a plan run

## Summary

Follow-up to #232. Two jobs, one commit:

1. **Cross-reference at the point of use.** A comment beside `otterdog_version`
   saying that editing that line now gets a plan run, and why — so the next
   person bumping the pin reads it where they are already looking, not in a
   workflow file they have no reason to open.
2. **The isolated acceptance test for #230's second criterion** — *"a PR that
   edits only `otterdog_version` triggers the plan check."*

## Why this needed its own PR

#232 could not demonstrate that criterion. It edited `.github/workflows/plan.yml`,
which the `paths:` filter **already matched before the fix**, so a `Plan` run on
that PR proved nothing about the newly added entry — and indeed one ran there
(`Plan: 0 to add, 0 to change, 0 to delete`,
[run 35856379839](https://github.com/vig-os/org-config/actions/runs/35856379839)).

This PR touches `justfile.project` and **nothing else**. Of the filter's four
entries, only the one #232 added can match it. So:

- a `Plan` check appearing on this PR is proof the fix works;
- its absence is proof it does not.

Either way the criterion is settled by observation rather than by reading the
YAML and believing it.

## Notes

- No `CHANGELOG.md` entry: this is a comment, with no user-visible behaviour
  change of its own. #232 carries the entry for the fix.
- The plan this triggers is expected to be **all zeros** — a comment in a
  justfile changes no org config. An empty plan is the *correct* result; the
  point is that the run happens at all, unprompted.

Refs: #230
