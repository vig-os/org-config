# [PR 302](https://github.com/vig-os/org-config/pull/302) chore(config): declare Tag and Release rulesets on devkit-smoke-test and org-config

## Description

PR 7 of the #294 plan. It declares the three rulesets that [ADR-0008](docs/adr/0008-repository-protection-and-merge-policy.md) left as follow-ups under #294:

- `org-config`: `Tag protection`
- `devkit-smoke-test`: `Tag protection` and `Release protection`

Both repos release through the devkit train. The bypass actors were checked against every ref writer in each repo's workflows on its default branch (via the Contents API for `devkit-smoke-test`). They are the same actors `h5v`, `scitadel`, `commit-action` and `sync-issues-action` already declare.

An **`org-config` `Release protection` ruleset is deliberately not included.** That decision is still pending.

### Bypass verification (devkit-smoke-test, default branch `main`)

App IDs come from `gh api orgs/vig-os/installations`: `commit-action-bot` = 2433383 and `vig-os-release-app` = 2930017. `devkit-smoke-test` has no repo secret named `token`, so every `secrets.token || release_app_token` fallback in the workflows resolves to the Release App.

**Writers of `release/*`**: only the Commit App (`COMMIT_APP_CLIENT_ID`), the Release protection bypass.

- `prepare-release.yml`: creates the branch with `POST git/refs`, commits the freeze through commit-action, and resets it on rollback with `PATCH git/refs`. All of these use `commit_app_token`.
- `prepare-hotfix.yml`: the same steps, all with `commit-app-token`.
- `release-core.yml`: the finalize commit goes to `refs/heads/release/X.Y.Z` through commit-action with `commit_app_token`.
- `sync-issues.yml`: dispatched onto `release/X.Y.Z`. It commits through commit-action with the Commit App token.
- `release.yml`: the rollback revert commit plus `PATCH git/refs`, with `commit_app_token`.
- The Release App only **deletes** `release/*`, in `abandon-release.yml` and in the stale-branch cleanup of `repository-dispatch.yml`. The shape sets `allows_deletions: true`, so no bypass is needed. The dispatch listener's deploy branch is `chore/deploy-*`, which is outside `release/*`.

**Writers of tags**: only the Release App (`RELEASE_APP_CLIENT_ID`), the Tag protection bypass.

- `release-publish.yml`: creates the release tag and each RC tag with `POST git/refs` (`refs/tags/...`) using the Release App token.
- `promote-release.yml`: prunes RC tags with `DELETE git/refs/tags` using `release_app_token`, and moves floating tags with `git push --force` using the Release App checkout credentials.
- `abandon-release.yml`: deletes the RC tag with the Release App token.
- Live precedent for `POST git/refs` passing the bypass: `sync-issues-action` runs the same `release-publish.yml` under an active `Tag protection` ruleset (19011483, bypass Integration 2930017). It published `v0.5.1` on 2026-09-28, with the tag created by `vig-os-release-app[bot]`.

**The required check can be met**: `devkit-smoke-test`'s `ci.yml` runs on `pull_request` into `dev`, `release/**` and `main`, and its `summary` job is named `CI Summary`. PRs into `release/*` therefore report the check. Train writes to `release/*` come from the Commit App, which bypasses it.

**org-config**: `release-publish.yml` creates the tag with the Release App token (L113-114 mint it, L177 `POST git/refs`). `promote-release.yml` prunes RC tags (L656) and moves floating tags (L791) with the Release App token. `org-config` is in the `RELEASE_APP_CLIENT_ID` / `RELEASE_APP_PRIVATE_KEY` selected-repository lists.

## Changelog Entry

### Changed

- **`devkit-smoke-test` and `org-config` gain the release rulesets [ADR-0008](docs/adr/0008-repository-protection-and-merge-policy.md) left as follow-ups** ([#294](https://github.com/vig-os/org-config/issues/294)): both repos cut releases through the devkit train, yet neither protected its tags, and `devkit-smoke-test` left `release/*` unprotected. Each ruleset was decided after checking every writer in the repo's workflows. Both repos gain `Tag protection` with `vig-os-release-app` as the only bypass, because the Release App is the only tag writer: `release-publish.yml` creates the release and RC tags, and `promote-release.yml` prunes RC tags and moves floating tags. **`devkit-smoke-test`** also gains `Release protection` on `release/*` (`15368:CI Summary`, which `ci.yml` reports on every PR into `release/**`, with a `commit-action-bot` bypass), because the Commit App is the only writer of release branches. The Release App only deletes them, which the shape allows. The two ADR-0008 exception rows that deferred these rulesets are removed.
