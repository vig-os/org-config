# [PR 102](https://github.com/vig-os/org-config/pull/102) fix(config): declare tessera dev protection and sync-app secrets

Declares three live-but-undeclared `tessera` resources that the drift sweep flagged as deletes:

| Resource | Drift issue |
|---|---|
| `branch_protection_rule[pattern="dev"]` | #87 |
| `repo_secret[name="APP_SYNC_ISSUES_ID"]` | #88 |
| `repo_secret[name="APP_SYNC_ISSUES_PRIVATE_KEY"]` | #86 |

## Why declare rather than delete

- **The secrets are a different App identity.** They hold the credentials of the **repo-scoped** `tessera-sync-issues-bot` GitHub App (app_id 4483218, installed 2026-08-04) — not the org-wide sync-issues App, despite the identical secret names. Deleting them would break tessera's issue-sync workflow, and folding them into org secrets would silently swap the App identity. An inline comment in the jsonnet records this so they are not "deduplicated" later.
- **The `dev` rule guards an active branch.** `tessera` uses `dev` as its live integration branch; the rule is a real gate, not a leftover.

Values are declared as `'********'` (managed out-of-band), the established convention in this file for pre-existing secrets.

## Status-check serialization note

The `dev` rule declares `required_status_checks: ['nix flake check']` **without** the `any:` prefix that `main`'s rule carries. The live check is app-bound (app_id 15368) and otterdog serialized it bare in the #87 plan diff, so the declaration matches what otterdog reads back.

Related risk: #69 tracks an otterdog 1.3.4 bug where an apply fails on any **ruleset** patch carrying a numeric `15368:`-style status check (upstream otterdog#695). This is a classic **branch protection rule**, not a ruleset, so it is not the same code path — but the plan check on this PR is to be read before merge specifically to confirm the `dev` rule serializes clean (no diff on the status-check field).

## Expected plan

The three deletes disappear, leaving `0 to add, 1 to change, 0 to delete` — the remaining change is the allowlisted `vs-dolt` `code_scanning_default_languages` artifact.

## Issue closure

No closing keywords: the drift layer auto-closes #86, #87, and #88 on the next drift run once the divergence is resolved (ADR-0002).
