# [PR 194](https://github.com/vig-os/org-config/pull/194) fix(workflow): move engine preview out of reusable apply workflow

## Description

Fixes the reusable-workflow permission-cap regression from #105 that has broken every template-scaffolded downstream `apply` caller since v1.1.0.

GitHub validates the caller-permission cap over **every** job in a called workflow's graph at assembly time, **before** `if:` is evaluated. The engine-only `preview` job inside `apply.yml` (gated `if: inputs.org_github_id == ''`, but declaring `pull-requests: write` because it nests `plan.yml`) therefore counted against the cap on every downstream call — and `template/.github/workflows/apply.yml` callers granting exactly `contents: read` died with `startup_failure`, zero jobs. Found by exo-pet's first apply dispatch on a v1.2.1 pin.

Fix (issue option 1): the preview moves to a new engine-only driver `.github/workflows/apply-engine.yml`, which takes over this repo's `push`/`workflow_dispatch` triggers and the literal cross-workflow `otterdog-mutate` concurrency group and runs `preview` + `apply` as two jobs of **one** run — the approver still sees the exact-tree plan in the same run as the production approval prompt. `apply.yml` becomes `workflow_call`-only with a single `contents: read` job, restoring the honest caller contract.

## Changes Made

- **NEW `.github/workflows/apply-engine.yml`** (`name: Apply`): engine-only driver with the push (main/dev, config-paths filter) + dispatch triggers, the `otterdog-mutate` group, `permissions: {}` at top level; `preview` job (`contents: read` + `pull-requests: write`, `uses: ./.github/workflows/plan.yml`, deliberately not a `needs:` of apply) and `apply` job granting **exactly `contents: read`** — byte-identical to the template caller's grant, so every engine apply live-tests the downstream contract. Secrets passed explicitly (no `secrets: inherit`), including `SOPS_AGE_KEY` which a called workflow can no longer read from repo scope.
- **`.github/workflows/apply.yml`**: renamed `Apply (reusable)`; `workflow_call`-only; `preview` job deleted; concurrency expression byte-identical (downstream contract) with its stale comment rewritten; header comments corrected; standing rule added: no job here may ever declare a permission beyond `contents: read`.
- **`.github/workflows/plan.yml`**: comment-only pointer fix.
- **`template/.github/workflows/apply.yml`**: +4 comment lines stating `contents: read` is the complete required grant — no logic change; no caller edit needed downstream.
- **`README.md`**: apply row of the workflow table updated.
- **`CHANGELOG.md`**: `### Fixed` entry under `## Unreleased`.
