# [PR 203](https://github.com/vig-os/org-config/pull/203) feat(workflow): apply-dispatch reminder for downstream orgs

## Summary

Closes #202.

On a private config repo below Enterprise, environment required reviewers are unavailable (HTTP 422), so apply is dispatch-only and a merged-but-unapplied config is a silent state — the first signal is the next daily drift run. This PR adds the tracker-issue reminder machinery designed in #202:

- **New reusable `.github/workflows/apply-reminder.yml`** (`workflow_call`-only): on a config merge, comments the pending apply (merge commit, PR link parsed from the guaranteed `(#N)` merge-title suffix, dispatch command) onto a pinned "Apply dispatch tracker" issue and sets a `pending-apply` label. No secrets, no checkout, no third-party actions; own `apply-reminder-<org>` concurrency group; same four-path filter as apply (`otterdog.json`, `otterdog/**`, `secrets/**`, `.sops.yaml`). With `tracker_issue` empty every run is a logged green no-op.
- **`apply.yml`: optional `tracker_issue` input** (string, default `''` = byte-identical). On a successful apply — guarded by `inputs.tracker_issue != '' && steps.apply.outcome != 'skipped' && steps.apply.outputs.rc == '0'` — it posts the applied confirmation on the tracker and clears the label, riding a **narrowed App token** (drift.yml's issue-ops pattern, `permission-issues: write` scoped to the caller's config repo). The job stays at `contents: read`, honoring the #176 standing rule, so no existing consumer is affected.
- **Template**: ships the reminder caller **active by default** (TODO placeholders, opt out by deleting the file); the apply caller now documents **Mode A** (public/Enterprise: reviewer-gated apply-on-merge) vs **Mode B** (private Team/Free: dispatch-only, the shipped default — its previous required-reviewer instruction 422s on private repos); `template/README.md` gains the four-step tracker onboarding runbook and `template/README.repo.md`'s flow description is corrected.
- **Docs/changelog**: root README notes the fourth reusable workflow under "Governing another organization"; `CHANGELOG.md` Unreleased gains Added + Changed entries (semver:minor).
