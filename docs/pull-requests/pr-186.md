# [PR 186](https://github.com/vig-os/org-config/pull/186) chore(config): dismiss stale reviews on sync-issues-action main

## Summary

Adds `dismisses_stale_reviews: true` to `sync-issues-action`'s **Main protection** ruleset (`otterdog/vig-os/vig-os.jsonnet`), with the same inline rationale devkit records under #118: an approval must cover the code being merged — without this, a review of one commit survives every later push, so the 1-approval gate can be satisfied by a commit nobody reviewed. Main only; Dev and Release require 0 approvals and have nothing to dismiss.

Everything else in the ruleset is unchanged (approval count 1, code-owner review, thread resolution, `CI Summary` + `Dist Check`, the `Signed commits` ruleset).

Deliberately **not** included, per the issue:
- `requires_last_push_approval` — blocks self-merge for a solo maintainer (declined for devkit under #118).
- `strict` up-to-date branches — separate decision; note devkit (`:408`) and commit-action (`:276`) both carry it, so sync-issues-action is now the only action repo without it.

## Verification

- Config and live ruleset (id 13401788) were confirmed in agreement before the change: `dismiss_stale_reviews_on_push: false`, no drift.
- Vendored otterdog defaults set `dismisses_stale_reviews: false`, so the previous omission genuinely meant off.
- Full hook suite (`just precommit`) green locally, otterdog validation 0 errors.
- Expected outcome on OpenSSF Scorecard alert [sync-issues-action#15](https://github.com/vig-os/sync-issues-action/security/code-scanning/15): improved score, alert **stays open** — its three remaining warnings are deliberate.

## Apply

Plan runs on this PR; apply converges the live ruleset on merge. Worst case the change forces a re-approval that should have been required anyway.
