# [PR 146](https://github.com/vig-os/org-config/pull/146) chore(config): retire the orphaned DOCKERHUB org secrets

## Description

Retires the orphaned `DOCKERHUB_TOKEN` and `DOCKERHUB_USERNAME` `vig-os` **organization** secrets, dropping both declarations from `otterdog/vig-os/vig-os.jsonnet` and superseding the empty-`selected_repositories` interim from #123.

They were never a mistake — they were collateral of the Debian → Nix migration in `devkit`:

| When | What |
|---|---|
| **2026-04-02** | `devkit` `36a40550` ("ci: authenticate Docker Hub pulls to avoid rate limits", vig-os/devkit#473) added `dockerhub-username`/`dockerhub-token` inputs to the `build-image` composite action and logged in to `docker.io` before `setup-buildx-action`. The two org secrets were created the **same day** (11:30 and 11:31 UTC) to feed it. |
| **2026-06-24** | `devkit` `1d4e9db1` ("build(nix): decommission the Debian build path", on `main` and `dev`) removed the login along with the path that needed it. Nothing has referenced either name since. |

The justification is gone as well as the consumer: the Nix path resolves `github:NixOS/nixpkgs` flake inputs, so nothing in the fleet anonymous-pulls from Docker Hub and there is no rate-limit exposure left to re-authenticate against.

**Zero consumers re-confirmed at retirement** (issue step 1), against **live default-branch trees rather than the code-search index** — the index returned only stale `docs/` hits from the 2026-04 PRs, which would have wrongly suggested `ci.yml`/`release.yml` still pass the secrets:

- 231 workflow and composite-action YAML files across all 14 org repos, fetched live from each repo's default branch
- plus every remote branch of `devkit`, including the `dev` integration branch
- **zero references** to either name
- all five surviving `docker/login-action` steps in `devkit` (`nix-image.yml` ×2, `promote-release.yml` ×2, `release.yml`) target `ghcr.io` with `github.token`
- `vs-dolt`'s `cd-push-docker-image.yaml` is the org's only remaining Docker Hub consumer and reads its **own repo-level** `DOCKER_HUB_USERNAME` / `DOCKER_HUB_ACCESS_TOKEN` (underscore after `DOCKER`, different scope) — deliberately untouched

Unlike the #111 precedent, the live org secrets were deleted by the org owner **before** this change merged, so `plan` carries no pending deletions (`otterdog apply` never deletes secrets, so the ordering affects only plan noise). The underlying Docker Hub access token was also revoked in Docker Hub — deleting a GitHub secret does not revoke the credential it held.
