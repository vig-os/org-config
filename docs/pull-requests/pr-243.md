# [PR 243](https://github.com/vig-os/org-config/pull/243) fix(lint): declare ubuntu-26.04 runner labels for actionlint

## Root cause

`actionlint` validates `runs-on:` against a **built-in** list of GitHub-hosted
runner labels, compiled into the binary. The repo's nix toolchain pins
**actionlint 1.7.12** — the *latest* upstream release (2026-03-30) — and the
`ubuntu-26.04` / `ubuntu-26.04-arm` hosted images shipped **after** it. So the
linter rejects them:

```
.github/workflows/<file>:NN:14: label "ubuntu-26.04" is unknown. available
labels are ... "ubuntu-24.04", "ubuntu-24.04-arm", "ubuntu-22.04", ... if it is
a custom label for self-hosted runner, set list of labels in actionlint.yaml
config file [runner-label]
```

This is **tool lag, not a code defect**: no pin bump recognises these labels,
because no actionlint release knows them yet. The only remedy actionlint itself
offers is the one its error message names — declare the labels in
`.github/actionlint.yaml`.

## What this unblocks

Two independent red pipelines fail on exactly this error and nothing else:

- the **devkit 1.16.0 automated upgrade run** —
  https://github.com/vig-os/org-config/actions/runs/35916200558
- **Renovate PR #222**

## Why by hand

devkit 1.16.0 ships a template `.github/actionlint.yaml` declaring these labels
(vig-os/devkit#1660), but this repo's `.github/actionlint.yaml` is
**preserved-class** — the upgrade deliberately does not overwrite it, since it
carries the repo's own #169 `job.workflow_sha` tool-lag ignore. The devkit
1.16.0 release notes prescribe a **by-hand fold** of the template baseline into
preserved configs; this PR is that fold.

The existing header comment and the `paths:` ignore block are untouched; the new
`self-hosted-runner:` block is appended, carrying its own rationale comment and
an explicit **DELETE BOTH once an actionlint release knows them** marker, so the
suppression does not outlive the lag.

## Verification

Performed locally in the nix shell, before and after:

1. **Negative control** — with the fix reverted, temporarily flipped one
   `runs-on: ubuntu-24.04` to `ubuntu-26.04`: actionlint failed with the
   `[runner-label]` error above. Confirms the diagnosis.
2. **Positive proof** — with the fix applied and that same temporary
   `ubuntu-26.04` edit still in the tree, the full hook suite (`just precommit`
   → `prek run --all-files`) ran **green**, actionlint included. Confirms the
   label is now accepted, not merely unreported.
3. The temporary workflow edit was then reverted completely, and the full suite
   re-run on the final tree — **all hooks green**, `yamllint` included.

The diff is a single file, 10 added lines, no deletions.
