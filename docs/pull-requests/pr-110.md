# Release 1.0.1

Patch release. Freezes the accumulated `## Unreleased` content into
`## [v1.0.1] - 2026-08-07` with a fresh empty `Unreleased`, produced by the house
`prepare-changelog prepare` + `finalize` pair with `--tag-prefix v`.

## What is in it

- **House defaults overlay** (#108) — `otterdog/vig-os/house-defaults.libsonnet`,
  a single source for the house repository merge policy, folded into `newRepo`
  and shipped downstream in `template/`. The `vig-os.jsonnet` dedup against it is
  a verified pure refactor (evaluated config byte-identical before and after).
- **`template/` retargeted to trunk `main`** (#106) — all eight `dev` references
  in the downstream skeleton, plus the example engine pins bumped to `v1.0.1`.
  This is the first release carrying a skeleton that matches the engine it calls,
  so it is the tag downstream orgs should re-pin to.

CHANGELOG only — `otterdog/`, `secrets/`, `src/`, and the workflows are untouched,
so this merge triggers no apply.

## Release mechanism

Same deviation as v1.0.0 (PR #104), for the same two reasons, both properties of
this repo's own governance rather than of the change:

1. `prepare-release.yml` commits the frozen CHANGELOG straight to `main` via
   `commit-action`; `org-config`'s `Main protection` ruleset requires a pull
   request and bypasses only `OrganizationAdmin`, so the bot push is rejected
   ([vig-os/devkit#1227](https://github.com/vig-os/devkit/issues/1227), whose
   resolution explicitly rules out granting the commit App a `main` bypass).
2. `release-core` requires an approved release PR for a final release, and the
   sole maintainer cannot approve their own PR.

So the freeze lands here as a reviewed PR using the same `prepare-changelog` tool
the pipeline runs, and the annotated signed tag plus the GitHub Release are
created from the merge commit with this CHANGELOG section as the notes — the same
shape `release-publish.yml` produces.
