# [PR 249](https://github.com/vig-os/org-config/pull/249) docs(controls): retire the stale private-repo ruleset read gate from the template

Closes #248.

## What

Documentation and template prose only. Three passages still asserted the
private-repo repository-ruleset **read gate** that otterdog 1.5.0 removed:

| File | Was |
|------|-----|
| `template/unmanaged-controls.toml:41` | *"Otterdog cannot read live rulesets on a private repo below Enterprise, so on a private Team-plan org they are precisely the controls with no other detector"* + "the two rows worth holding" |
| `README.md:73` | *"…assertable, which matters most on a private repo where Otterdog cannot read rulesets at all"* |
| `unmanaged-controls.toml:277` | *"held for downstream orgs on Team/Enterprise, whose private repos otterdog cannot read (#107, eclipse-csi/otterdog#729) while REST can"* |

## Why it is false

[#225](https://github.com/vig-os/org-config/issues/225) moved the pin to otterdog
**1.5.0**, shipped in engine **v1.4.0**. Upstream
[eclipse-csi/otterdog#731](https://github.com/eclipse-csi/otterdog/pull/731)
removed the plan-and-visibility gate from **both** ruleset read paths — the fix
that closed [#107](https://github.com/vig-os/org-config/issues/107) /
[upstream #729](https://github.com/eclipse-csi/otterdog/issues/729) and released
the [#205](https://github.com/vig-os/org-config/issues/205) downstream
conversions. Repository rulesets are now read on every plan tier and both repo
visibilities, so the fields otterdog's schema models are plan-diffed everywhere
and a row asserting one *duplicates a modelled control* — which is exactly what
the shipped table's own comment rejects, while the template was recommending it.
`README.md`'s "Known limitations" section already recorded the correction, so the
repo contradicted itself.

## What replaces it

Each passage now says **when a row is warranted** rather than which repos are
unreadable:

- a rule parameter otterdog does not model
  ([#246](https://github.com/vig-os/org-config/issues/246),
  [upstream #768](https://github.com/eclipse-csi/otterdog/issues/768));
- a ruleset deliberately kept out of the config;
- **organization**-level rulesets — the stronger case now: #731 made them
  readable, but `GitHubOrganization.validate()` still refuses to declare any
  below Enterprise
  ([upstream #763](https://github.com/eclipse-csi/otterdog/issues/763)), so they
  stay hand-managed and a row here is their only detector.

The two example rows in the template are byte-identical, re-labelled as *the
shape a row takes* rather than rows to hold by default, so the starter still
teaches the `/repos/{org}/{repo}/rules/branches/{branch}` form and the
`compare = "set"` semantics.

## Deliberately untouched

- `docs/issues/*.md`, `docs/pull-requests/*.md` — archival records of what was
  true when written.
- `template/README.md:212` — already reads "previously unreadable" (past tense,
  correct).
- The `otterdog-defaults` `v0.13.1` pin — held for the `max_cache_size_gb` /
  HTTP 402 reason, unrelated to reads.
