# [PR 320](https://github.com/vig-os/org-config/pull/320) fix(config): drop revkit from the numeric App ID org secrets

## Description

Resolves the last divergence in drift #313 (`unmanaged-control:org:org-secret-repositories`). Since the issue was opened, revkit has been granted the six client-ID-form App secrets live by hand (`COMMIT_APP_CLIENT_ID`/`_PRIVATE_KEY`, `RELEASE_APP_CLIENT_ID`/`_PRIVATE_KEY`, `DEVKIT_UPGRADE_APP_CLIENT_ID`/`_PRIVATE_KEY`). The only config-only entries left are `revkit` on the numeric `COMMIT_APP_ID` and `RELEASE_APP_ID`. Live readers, checked 2026-10-04:

```text
COMMIT_APP_ID:  commit-action,h5v,scitadel,sync-issues-action
RELEASE_APP_ID: h5v,scitadel
```

**Decision: drop the entries from the config. Do not grant them live.**

- revkit is a devkit 1.17.0 scaffold. It reads only the client-ID form. A sweep of all 15 files in `vig-os/revkit/.github/workflows` found no `secrets.COMMIT_APP_ID` or `secrets.RELEASE_APP_ID` read. Every commit and release token is minted from `*_CLIENT_ID` + `*_PRIVATE_KEY`. The only numeric reference is `devkit-upgrade.yml`'s legacy `DEVKIT_UPGRADE_APP_ID` fallback, and revkit is correctly not declared on that secret.
- #315 is retiring the numeric App-ID secrets. Granting revkit would add one more reader for that retirement to clear.
- The entries came in with #312, which copied `scitadel`'s eight-secret list. stepv (#317) and tessera (#252) are on the client-ID form from day one and are already deliberately absent from the numeric lists. revkit now matches them.
