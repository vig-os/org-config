# [PR 239](https://github.com/vig-os/org-config/pull/239) docs(adr): decide the Plan check stays advisory (ADR-0007 Axis D)

Closes #236.

## What

Records the decision #236 asked for: **the `Plan` check stays advisory**, and
ADR-0007 now says so explicitly instead of by accident.

- New **Axis D** in the mandatory alternatives table: advisory (chosen),
  require-as-is (unavailable — a path-filtered workflow's check pends forever),
  job-level skip shim + static summary job (viable, rejected for now),
  require-where-it-runs (not expressible), fail-on-diff (inverts ADR-0002).
- The L2 bullet gains an "advisory by decision, not by accident" clause with the
  three-part reasoning: a red plan signals runner/auth health rather than PR
  content (`plan` exits 0 on a non-empty diff); config validity is already
  behind `CI Summary` via the `otterdog validate` L0 hook; the diff itself is
  explicitly not a failure under ADR-0002. The enforcing control sits at the
  mutation boundary — the `production` reviewer with the exact tree's plan in
  the same run (#105, #176), plus the tip-of-branch guard (#99).
- Consequences spell out what is accepted (an unintended diff can merge on
  green CI; blast radius is a commit, not an applied org) and that `Main
  protection` deliberately gains no second context on a solo-maintained repo
  with an unconditional admin bypass (#115/#167/#195/#226 pathology).
- The open-question trigger #235 added is replaced by the decided state with
  three revisit triggers: an unintended diff the `production` approval misses,
  a second maintainer, or GitHub shipping path-conditional required checks.

## Notes for review

- The skip-shim option is real and cheaper than #236 assumed (a job skipped by
  an `if:` conditional reports *Success* and satisfies a required check, per
  GitHub docs — this repo already relies on that in `CI Summary`), so it is
  rejected on cost of meaning, not cost of compute; the full implementation
  sketch lives in #236's evaluation and can be revived against a real incident.
- Empirical footing: `plan.yml` has run 57 times and never once concluded
  `failure`.
- No implementation issue is spun off — the decision is "stay advisory".
- Documentation only; `plan.yml` and `Main protection` are byte-identical, so
  no plan run is expected on this PR.
