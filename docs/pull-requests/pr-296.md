# [PR 296](https://github.com/vig-os/org-config/pull/296) docs(app): record the verified devkit-upgrade visibility and its two-org flip gate

## Summary

`#271` recorded `vigos-devkit-upgrade` as public **"pending the UI verification below"**, because
`GET /apps/{app_slug}` carries no visibility field and the only API signal was the status code to an
anonymous caller. That reading was taken on 2026-09-28 and found more than a confirmation, so this
change removes the hedge in both directions.

**The reading.** An owner of the `vig-os` organization opened *Settings → Developer settings →
GitHub Apps → `vigos-devkit-upgrade` → Advanced* and read, under **Danger zone**, three controls in
this order: "Transfer ownership of this GitHub App", "Delete this GitHub App", **"Make this GitHub
App private"** — the third **greyed out**, subtitled *"Private GitHub Apps cannot be installed on
other accounts."* The button names the *action*, so the live value is **public** — what the
anonymous `200` predicted (re-probed 2026-09-28). Identical in text, order and disabled state to
what #261 / #290 read on the engine App the same day: a second agreeing reading of that mapping, on
a second App, and still corroboration rather than the contract GitHub declines to publish.

**The finding: this App's flip is blocked harder than the engine App's.** GitHub states the rule —
*"Public apps cannot be made private if they're installed on other accounts"* — and the disabled
control is that rule enforced in the product. Re-verified 2026-09-28 with
`gh api /orgs/<org>/installations` across all four orgs:

| Org | `vigos-devkit-upgrade` installation | Created |
|-----|-------------------------------------|---------|
| `vig-os` (owner) | `150058891` | 2026-07-30T12:53:44+02:00 |
| `exo-pet` | `151387251` | 2026-08-05T09:28:31+02:00 |
| `exoma-ch` | `162764177` | 2026-09-18T15:53:42+02:00 |
| `MorePET` | none | — |

**Two** foreign installations against the engine App's one. The `exoma-ch` installation was missing
from the record — #271 named `exo-pet` as *the* foreign installation and argued the posture from it
in the singular, though `exoma-ch` had been installed for ten days by then. The argument held; the
evidence under it was short by one org, and the cost of a flip was understated by a whole org.

## Changes

- **`otterdog/vig-os/vig-os.jsonnet`** — the `APP VISIBILITY DECISION` comment:
  - drops "pending the UI verification below" for the reading, its date, who took it and the three
    Danger-zone control texts in the order seen;
  - records both foreign installations with ids and dates, and `MorePET` as carrying none;
  - adds a paragraph pricing the flip as **uninstall-gated in two orgs**, sequentially, with the
    devkit-upgrade automation outage in each a **precondition to the button being clickable at
    all** rather than a consequence of clicking it (that workflow mints its token from
    `DEVKIT_UPGRADE_APP_CLIENT_ID` / `DEVKIT_UPGRADE_APP_PRIVATE_KEY` —
    `.github/workflows/devkit-upgrade.yml:90`);
  - "VERIFICATION IS UI-ONLY, **and still owed**" becomes "no longer owed", keeping the
    observation-vs-contract split and the "button names the ACTION, not the state" trap, and telling
    the next reader to **expect a disabled button and read it anyway**;
  - corrects "the `exo-pet` installation is the only thing keeping it public" to the two.
- **`docs/runbooks/github-app.md:259`** — the grant-table bullet in **Visibility** no longer calls
  this App's verification pending; it points at the now-verified jsonnet comment and states the
  two-org cost, **reusing** the `[app-modify]` reference #290 added rather than a duplicate.
- **`CHANGELOG.md`** — one **new** bullet under `## Unreleased` → `### Changed`, per #290's
  precedent of recording a later reading as its own entry. The #271 bullet is untouched.
