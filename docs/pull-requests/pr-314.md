# [PR 314](https://github.com/vig-os/org-config/pull/314) chore(config): archive qms after content migration

## Description

Carries out option (c) of #306. `qms` is the one repo [ADR-0008](docs/adr/0008-repository-protection-and-merge-policy.md) left **Deferred**. Its content was migrated to the destination org's controlled-document store, and that ingestion was verified on 2026-09-30, so the repository is archived. Its history stays read-only and private. It contains committed licensed standards PDFs, which is one reason it stays private.

## Changes Made

Two commits, in the same order as #300 to #304:

1. `docs(adr)`: ADR-0008
   - drops the `qms` **Deferred** row from the Tiers table and the `qms` row from the Exceptions table.
   - adds a Corrections entry dated 2026-09-30. It records that #306 archives `qms`, which reverses the ADR's "no archiving" stance for this one repo only. The reason: a private repo on a Free-plan org can never carry an enforceable ruleset, and its content moved to an org whose plan enforces them.
   - rewords the plan-change trigger to "private repos become protectable" so that it no longer names `qms`.
2. `chore(config)`: in `otterdog/vig-os/vig-os.jsonnet`, the `qms` block sets `archived: true`. **Every other field is unchanged**, because an archived repo cannot be edited afterwards. The five restated legacy merge fields, `allow_forking`, `default_branch` and `private` all stay at their frozen live values. The "OUT OF SCOPE … until it gets its own decision (#294)" comment now records the decision instead. The same commit adds the CHANGELOG line.

`qms` stays declared, so the inventory sweep and `DECLARED_REPOS` do not change. The README and `unmanaged-controls.toml` passages about `qms` being private on Free are still true, so they are left as they are.
