# [PR 286](https://github.com/vig-os/org-config/pull/286) docs(secrets): record why the devkit-upgrade App is public

## Description

Issue #271: `vigos-devkit-upgrade` is the second public `vig-os`-owned App and, unlike the engine
App after #261, had **no recorded visibility decision anywhere** — not in this repo, not in
`vig-os/devkit`, not in an ADR — while answering `200` to an anonymous
`GET /apps/vigos-devkit-upgrade` (re-probed 2026-09-28; three sibling `vig-os`-owned Apps answer
`404`).

This takes the issue's recommended option 1 and nothing more: the decision is **recorded, not
changed**. The posture stays **public — *Any account* — decided 2026-09-28 and pending the UI
verification**, hedged exactly as #261 is, because `GET /apps/{app_slug}` carries no visibility
field and the only API signal is that anonymous status code. Public is a property of the live
topology rather than a preference: the App is installed on `exo-pet` (installation `151387251`) as
well as `vig-os`, and GitHub's private setting means installable only on the owning account, so
that installation could not exist under it — the one-App/N-installations model ADR-0004 chose.

Two things are stated rather than left to be inferred, and they are the substance of the record:
the grant is **five** permissions (`contents`, `issues`, `pull_requests`, `workflows` write and
`metadata` read — no `organization_administration`, no secrets, no members) against the engine
App's **seventeen**, so what an unauthenticated reader learns is narrow and what it does not learn
is spelled out; and the #256 bypass-actor coupling **does not bind** here, because this App is named
as a ruleset bypass actor nowhere in `otterdog/vig-os/vig-os.jsonnet` (#81 proposed exactly that and
was closed as superseded by vig-os/devkit#1308).

**This PR does not confirm the live UI value.** Reading *Settings → Developer settings → GitHub Apps
→ vigos-devkit-upgrade → Advanced → "Where can this GitHub App be installed?"* remains a human step
(with #261's trap: the Danger-zone button names the action, not the state), so the first acceptance
box of #271 stays open until an org owner walks it. No flip is proposed or performed.

## Changes Made

- `otterdog/vig-os/vig-os.jsonnet:115-181` — a new `APP VISIBILITY DECISION` comment above the
  `DEVKIT_UPGRADE_APP_*` declarations, beside the `MAINTENANCE COUPLING` note already there and in
  its style. That block is the App's only appearance in code anywhere, which is why the decision
  lives there. It carries: the decision and its hedge; the `exo-pet` installation as the reason;
  the five-permission grant and exactly what an anonymous `GET /apps/…` does and does not publish;
  the two accepted costs, with the `GET /app/installations` sweep written in as a step of
  `DEVKIT_UPGRADE_APP_PRIVATE_KEY`'s rotation (the only compensating control, and the one moment it
  is free); why #256 does not bind; and the UI-only verification path. **No declaration, secret,
  repository list or ruleset is touched — comment only, `otterdog validate` passes.**
- `docs/runbooks/github-app.md` — the **Visibility** section's world-readable-grant-table bullet
  described this App as *"the one still lacking a decision of its own"*; it now cross-references the
  recorded decision and names the three ways this App differs (narrower grant, no #256 coupling,
  a different key's rotation). One bullet changed; the engine App's own decision, flip checklist and
  verification steps are untouched.
- `CHANGELOG.md` — one bullet under `## Unreleased` → `### Changed`.
