# [PR 170](https://github.com/vig-os/org-config/pull/170) fix(drift): make the reusable drift workflow self-contained downstream

The reusable `drift.yml` ran the drift-layer reconciler from the **caller's** checkout, so no downstream consumer could run drift (`template/drift.yml` shipped with a "keep drift disabled" caveat and both READMEs carried the known-limitation).

On downstream runs (`github.repository != 'vig-os/org-config'`) the workflow now:
- guards that `job.workflow_sha` is non-empty (loud failure instead of a silent unpinned checkout),
- checks out this public engine repo at that SHA — the commit of the called reusable-workflow file, i.e. automatically the exact SHA the caller pins in `uses:` (single pin, no skew, Renovate bumps both atomically) — into `.drift-engine/`, **after** the plan leg so `otterdog plan` provably runs on an untouched caller tree,
- runs `uv run --project "${DRIFT_PROJECT_DIR}" drift-layer …` with cwd (and all data paths) still in the caller's checkout.

Engine own-run semantics stay byte-identical: both new steps are skipped and `--project '.'` is today's behavior. `template/drift.yml` now ships enabled; READMEs updated; changelog entry under Unreleased.

`.github/actionlint.yaml` is new: a single tool-lag suppression scoped to drift.yml — actionlint ≤ 1.7.12 models the `job` context without the documented `job.workflow_sha` (the `github.job_workflow_sha` predecessor was the buggy actions/runner#2417; the `job.*` properties supersede it).

Runtime validation of the downstream leg lands with the first consumer adoption (exo-pet, planned next); the guard step turns any surprise into a loud red run rather than skew.
