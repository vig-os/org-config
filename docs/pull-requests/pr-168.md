# [PR 168](https://github.com/vig-os/org-config/pull/168) chore(config): drop the human-review requirement on devkit-smoke-test main

Implements #167: `required_approving_review_count` 1 → 0 on `devkit-smoke-test`'s `Main protection`, with the inline comment rewritten to record the new rationale, plus the matching `Unreleased` changelog entry. Everything else in the ruleset is unchanged (PR required, `CI Summary` status check, `#OrganizationAdmin` bypass).

**Why:** the count-1 requirement existed only so the dispatch listener's final-release gate could poll `reviewDecision`, which GitHub computes solely when the base branch requires reviews (vig-os/devkit#1391) — a workaround, not a control. The gate is removed in devkit by vig-os/devkit#1506, part of the single-approval release train (vig-os/devkit#1504). The operative controls are the required `CI Summary` check and devkit's published-smoke-release validation at promote; count-0-with-required-checks matches devkit's own Dev and Release protections.

**Sequencing (from #167):** apply together with the devkit-side listener change — both must land before the next devkit release train. Either half alone breaks the train: old poll + count 0 → empty `reviewDecision` → timeout; new listener + count 1 → unapprovable merge. If vig-os/devkit#1506 is not yet propagated to `devkit-smoke-test` when this merges, hold the `production` environment approval on the apply run until it is.

The plan workflow's diff on this PR should show exactly one ruleset mutation. Local `otterdog validate` passes (0 errors; the two `Bad credentials` warnings on `vs-dolt` / `vigos-mvp` are a local-token artifact, unrelated).
