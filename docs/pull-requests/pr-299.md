# [PR 299](https://github.com/vig-os/org-config/pull/299) chore(config)!: house protection shapes, Main standard and merge-commit-only (ADR-0008)

## Description

PR 2 of the #294 plan. It adds ADR-0008, which states the org's rule for repository protection and merge policy. It encodes that rule as ruleset shapes in `house-defaults.libsonnet`, declares every existing ruleset repo through those shapes, brings each `Main protection` to the house standard, and retires `legacyMergePolicy`.

No rulesets are added to unprotected repos (that is PR 3). `scitadel` and `tessera` are untouched (PRs 4 and 6). `qms` is out of scope and does not change live.

## Changes Made

Six commits, each reviewable on its own:

1. `docs(adr)`: `docs/adr/0008-repository-protection-and-merge-policy.md` plus its index row. It covers the tiers (A releasing, B active without an aggregator, exempt testbed, deferred `qms`), the Main standard, merge-commit-only, the delete-branch and secret-scanning defaults, the Free-plan and #246 constraints, and an explicit **exceptions table**.
2. `feat(otterdog)`: `mainProtection(checks)`, `devProtection(checks, bypass)`, `releaseProtection(checks, bypass)`, `signedCommits()` and `tagProtection(bypass)` in `house-defaults.libsonnet`. They are org-neutral, and the template copy is byte-identical. This commit is additive only: the evaluated config is unchanged.
3. `refactor(config)`: Dev, Release, Signed and Tag rulesets on the five ruleset repos move onto the shapes. The evaluated jsonnet is **byte-identical** (`cmp`).
4. `chore(config)`: every Main protection is declared with `orgs.mainProtection`. The live changes are listed below.
5. `chore(config)!`: `h5v`, `nvd-mirror`, `qx`, `vigos-mvp` and `vs-dolt` move to the house merge policy and drop their `allow_update_branch` / `delete_branch_on_merge` false overrides. `legacyMergePolicy` is deleted, which is a **breaking** template-contract change. The five fields of `qms` are restated inline, so its plan is a no-op. The READMEs are updated.
6. `chore(config)`: `org-config` Main requires 1 approval (decided on review). Its 0-approval override and the ADR exception row are removed.

Nothing else changes, including `qms`, `scitadel`, `tessera` and `org-config-testbed`.

### Exceptions kept (ADR-0008 table, commented at each override)

- `devkit-smoke-test` Main: **0 approvals**, **not strict**, **no thread-resolution gate**. Its PRs into `main` are bot-authored and merged by devkit's unattended release train (#167, vig-os/devkit#1506). `promote-release` fails on `BEHIND` with no human there to update the branch.
