# [PR 251](https://github.com/vig-os/org-config/pull/251) ci(renovate): bump the otterdog pin by custom manager, adopted by review

Closes #250.

Renovate now proposes the ADR-0005 otterdog pin bump; a human still adopts it.

## What changed

`renovate.json` enables `custom.regex` and defines one manager keyed off a
`# renovate: datasource=pypi depName=otterdog` marker placed directly above each
of the five pin literals:

| Site | Shape |
|---|---|
| `justfile.project` | `otterdog_version := "1.5.0"` (the ADR-0005 SSoT) |
| `.github/workflows/{plan,apply,drift}.yml` | the `workflow_call` input `default:` |
| `template/.github/workflows/import.yml` | the standalone bootstrap's own literal |

All five carry one `depName`, so Renovate raises a **single** PR covering them.

**Why markers rather than a bare pattern.** Those workflow files mention
`otterdog_version` in prose as well as as an input key — `plan.yml` even quotes a
past bump, "1.4.0 -> 1.5.0", inside a comment — so a regex anchored on the key
name alone sits one edit away from silently matching the wrong line. Silence is
this pin's historical failure mode (the 1.4.0 bump missed `import.yml` entirely,
#164 item 7), so the form that fails loudly wins.

## The review gate, stated honestly

The rule sets `automerge: false`, requests review, and labels the PR `area:ci`.
`plan` runs on it because #230 put `justfile.project` in the workflow's `paths:`
filter, so the empty-plan evidence #225 had to dispatch by hand now arrives on
the PR for the reviewer to read.

**This is a requested review, not an enforced one, and no ruleset can make it
enforced here.** Verified live rather than assumed:

- `Main protection` (`19092020`) grants `OrganizationAdmin` an `always` bypass,
  so the maintainer bypasses every rule in it when merging;
- `required_approving_review_count` is `0` by decision (#167) — a sole maintainer
  cannot self-approve, so raising it would block every human PR, not this bot's;
- `require_extra_approval_for_unattributed_changes: true` does not reach bot PRs
  at all: the 8 most recently merged `app/renovate` PRs (#207, #208, #212,
  #216–#218, #221, #222) all report an empty `reviewDecision`.

The config comment says this, so a later reader does not mistake it for a hard
gate.

## The guard

`tests/test_otterdog_pin.py` is therefore the only mechanical check, and grows
three assertions beyond its existing mirror-equality ones (committed first, red,
in `8db89ea`):

1. every pin site carries its marker — deleting one silently drops that site from
   Renovate and restores the hand-edit failure mode;
2. `custom.regex` stays in `enabledManagers`, an allowlist where an omission
   disables the manager entirely;
3. the manager's own `matchStrings` are read out of `renovate.json`, compiled and
   run against the real files, asserting exactly one match per site carrying the
   SSoT value.

(3) is what makes "the regex is validated, not assumed" a checked claim. It
translates Renovate's JS/re2 named groups to `re` spelling, which is faithful for
the shapes used here (no lookbehind); it checks intent, while
`renovate-config-validator` checks syntax.

## Deliberate exclusions

- **`otterdog.json`'s `otterdog-defaults` pin** stays outside the manager's file
  patterns. It is held at `v0.13.1` because `v0.14.x` introduces
  `max_cache_size_gb`, whose endpoint answers `402` on a Free plan and writes a
  permanent `WARNING` into every `plan.txt` the drift layer parses. The two pins
  are not in lockstep.
- **`template/renovate.json` is unchanged**, so no downstream org inherits a
  custom manager it would have to maintain. The marker shipped in
  `template/.github/workflows/import.yml` is read by this repo's Renovate and is
  inert in an instantiated consumer — deliberately, since that bootstrap is
  dispatched once at onboarding. The file now says so.

## Verification

- `just test` — 145 passed (18 in `test_otterdog_pin.py`, up from 7 sites' worth).
- `just precommit` — full suite green, exit 0.
- `renovate-config-validator` — `Config validated successfully`.

ADR-0005 gets a new dated Corrections entry; the 2026-09-23 one stands, because
its diagnosis was right — only the conclusion drawn from it is superseded.

## Not done here

The pin stays at **1.5.0**. otterdog 1.6.0 exists but changes nothing this org
uses (no new modelled settings, so no new plan diffs; upstream #768/#763/#738 all
still open), so adopting it is a separate decision — and the first thing this
manager will now offer.
