# [PR 290](https://github.com/vig-os/org-config/pull/290) docs(app): record the verified App visibility and the uninstall-gated flip

## Description

Closes #261 by converting its last open acceptance box into a recorded reading, and by writing down
what that reading turned up: the visibility flip this section costs out is not a toggle at the
moment.

An owner of the `vig-os` organization walked the runbook's own **Verifying the setting** checklist on
**2026-09-28**. Under **Danger zone** on the App's **Advanced** page the three controls read, in
order: "Transfer ownership of this GitHub App", "Delete this GitHub App", **"Make this GitHub App
private"**. The button names the *action*, so the live value is **public** — the value the checklist
predicted from the anonymous `200`, now agreed with by the form GitHub treats as the authority.

The second half of that reading is the substantive content: **the control is greyed out.** GitHub
documents why, on the page adjacent to the reference the section already cited — *"Public apps
cannot be made private if they're installed on other accounts"*
([Modifying a GitHub App registration](https://docs.github.com/en/apps/maintaining-github-apps/modifying-a-github-app-registration#changing-the-visibility-of-a-github-app))
— and the button's subtitle says the same from the other side, *"Private GitHub Apps cannot be
installed on other accounts."* Re-verified 2026-09-28 with `gh api /orgs/<org>/installations` across
all four orgs this engine serves: `vig-os-org-config` is installed on its owner `vig-os`
(installation `147168870`, created 2026-07-17T12:00:45+02:00) **and on `exo-pet`** (`147219320`,
created 2026-07-17T16:40:50+02:00); `exoma-ch` and `MorePET` carry no installation of it.

So the flip is a sequenced two-org operation before it is a documentation edit: uninstall from
`exo-pet` first, which takes that org's org-config engine **offline** (its `plan`, `apply` and
`drift` legs all mint tokens from this App's `ORG_CONFIG_APP_CLIENT_ID` /
`ORG_CONFIG_APP_PRIVATE_KEY`), then flip the button on `vig-os`, then re-onboard. The flip checklist
now opens with that.

**On the scope of the fourth change.** The grant-table bullet in the same **Visibility** section
still pointed at #270 as an open question ("whether it stays a secret or becomes a variable is
#270"), which went stale when #270 was decided and closed. It now points at the recorded decision in
**Bootstrap secrets** and carries the corollary a reader of that bullet needs — finding the Client ID
published is *not* a rotation trigger; the PEM is. That edit is inside the section #261 governs and
was written while #261 was open, so it belongs here rather than in a follow-up; it is not a drive-by.

Deliberately out of scope: the `vigos-devkit-upgrade` twin (#271) keeps its "pending its UI
verification" hedge — its Danger-zone button has not been read.

## Additional Notes

**No `unmanaged-controls.toml` row is possible for this**, and the section already says why: the only
signal that discriminates public from private is the status code to an *unauthenticated* call, and
the controls transport reads authenticated, so it can never observe the discriminator. The check
stays a UI checklist by necessity, not by preference.

The observation-vs-contract split is kept deliberately on both findings. The private-App constraint
is written **as documented**, with GitHub's sentence quoted, because the doc does state it — the
greyed-out button is corroboration, not the source. The public/`404` status-code mapping stays an
**observation**, now with one confirming reading against the form, because GitHub documents neither
that mapping nor the endpoint's auth requirements.
