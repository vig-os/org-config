# [PR 275](https://github.com/vig-os/org-config/pull/275) fix(config): declare tessera's release-plz App secrets

Declares the two live-but-undeclared `tessera` repo secrets that the drift sweep flagged as deletes:

| Resource | Drift issue |
|---|---|
| `repo_secret[name="RP_APP_ID"]` | #255 |
| `repo_secret[name="RP_APP_PRIVATE_KEY"]` | #254 |

Both hold the credentials of the **repo-scoped** `tessera-release-plz` GitHub App (app_id 5050387, created 2026-09-23), which drives tessera's release-plz release-PR flow (tessera ADR-0052). They were created out-of-band and never declared, so every plan proposed deleting them — a deletion that would break every release PR on the repo.

Values are declared as `'********'` (managed out-of-band), the established convention in this file for pre-existing secrets. The rows sit beside `tessera`'s existing repo-scoped `APP_SYNC_ISSUES_*` pair, with an inline comment recording the App identity and the retirement condition.

## Why declare rather than delete

Owner decision: **tessera stays on release-plz through its alpha series.** Migrating it to the devkit release train is deferred to graduation and tracked in [tessera#441](https://github.com/vig-os/tessera/issues/441). Until then the App is load-bearing, so the credentials are adopted into config rather than reverted. The inline comment says to retire both rows together with release-plz when that migration lands, so the declaration does not outlive its reason.

This follows the register set by #102 for tessera's other repo-scoped App secrets (#86/#88).

## What changes live

**Nothing.** The value is the `'********'` placeholder, so otterdog marks the secret `include_for_live_patch: false` and an apply writes no value. The only effect is on the plan: the two proposed deletes disappear. Apply is auto-queued by the apply-engine and waits on the production gate as usual.

Closes #254
