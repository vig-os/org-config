# [PR 127](https://github.com/vig-os/org-config/pull/127) chore(config): require a human approval on devkit-smoke-test main

Bumps `devkit-smoke-test` → `Main protection` → `required_approving_review_count` from 0 to **1**.

**Why**: the smoke dispatch listener's final-release gate (vig-os/devkit#1391, devkit PR #1392) polls `reviewDecision`, which GitHub only computes when the base branch *requires* reviews. With count 0, the maintainer's approval on the smoke release PR never surfaces as `reviewDecision=APPROVED` and the gate times out — exactly what happened on the devkit 1.7.0 final leg (smoke run 31221248513). Workflow-token approvals are blocked org-wide (#122), so the required review is necessarily human — matching devkit's own main protection.

**Immediate effect after apply**: smoke PR #350 (approved last night) computes `APPROVED`; re-running the failed listener jobs resumes the devkit 1.7.0 final chain.

Validation: `just validate` green (jsonnetfmt OK, otterdog 0 errors).
