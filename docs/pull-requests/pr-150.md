# [PR 150](https://github.com/vig-os/org-config/pull/150) ci(apply): guard against superseded trees and preview the plan for approval

## Summary

Closes the #105 hole (approval gates the *run*, not the *tree*) with the first and third guards proposed there:

1. **Supersession self-guard** — first step of the gated `apply` job (i.e. the first thing to execute *after* the production approval, the only moment the check is meaningful) compares `github.sha` with the live tip of the applied branch via the API. On mismatch: every subsequent step skips, the job stays green, and a `::notice::` + job summary explain that the newer queued apply carries the delta. Consequence (documented in the header): re-running an old run can never apply an old tree — re-applying the current state takes a fresh `workflow_dispatch`.
2. **Pre-approval plan preview** — new ungated, read-only `preview` job that runs the *exact* tree's plan into the same run's job summary, one click from the approve button. Reuses `plan.yml` via a local `workflow_call` (single source of the plan harness) with two enabling tweaks: `plan.yml`'s fork-PR guard now also admits `push` (fork-safe by construction — a fork cannot push to the base repo), and the preview is gated to this repo's own events via the empty-`inputs` test, so downstream template callers (#56) are byte-identically unaffected. Deliberately **not** a `needs:` of `apply`: a preview harness failure must never block a legitimate apply.

Not taken: the cancel-superseded-runs variant (needs `actions: write` on a separate trigger; the self-guard already makes a superseded run die harmlessly at its own first step).

## Verification

- L0 green locally: `just precommit` (actionlint, zizmor — no new findings, both new/changed `run:` blocks use env-indirection — yamllint, full hook suite) and 43/43 tests.
- Happy path (`superseded=false`) is exercised by this PR's own post-merge apply.
- The superseded path is only reachable in a real race (two merges before one approval); its logic is a single API read + string compare, and its skip semantics reuse the existing `steps.apply.outcome != 'skipped'` conditions on the report/fail steps.
