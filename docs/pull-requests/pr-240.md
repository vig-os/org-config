# [PR 240](https://github.com/vig-os/org-config/pull/240) feat(workflows): default otterdog_version to the engine pin on workflow_call

Closes #228.

## What

`otterdog_version` now defaults to the engine's own pin (`1.5.0`) in the
`workflow_call` inputs of `plan.yml`, `apply.yml` and `drift.yml`, so a
downstream caller inherits the otterdog version with the engine ref it already
pins — #56's "Renovate can bump both" never held (no enabled manager matches a
bare `with:` string). The `template/` plan/apply/drift callers drop the input
and the BY-HAND comment; a consumer that wants a different version still passes
the input.

## Correction against the issue as filed

The issue claimed a `workflow_call` default is "visible only to callers". It is
not: `apply-engine.yml` reaches `plan.yml`/`apply.yml` **through**
`workflow_call` with no `with:`, so the bare proposal would have made the
engine's own preview and apply resolve the pin from a workflow literal instead
of `justfile.project`, quietly inverting ADR-0005. Both jobs now pass an
explicit `otterdog_version: ''`, keeping the justfile the effective resolver
for every run this repo triggers itself.

## Acceptance checklist mapping

- Defaults in all three workflows ✔ (commit 2)
- CI asserts defaults equal `justfile.project` ✔ — new
  `tests/test_otterdog_pin.py` (TDD: committed red first, `4 failed, 3 passed`
  against the old `''` defaults), reaching the required `CI Summary` through
  the managed `test` job; `ci.yml` untouched per ADR-0007. Also asserts
  `template/import.yml`'s literal (the standalone bootstrap keeps its own — it
  is the literal the 1.4.0 bump missed, #164 item 7) and that the template
  callers do not re-grow a `with:` literal.
- Template callers drop the input + comment ✔; `template/plan.yml`'s #230
  paths-filter comment re-argued.
- Onboarding docs ✔ — `template/README.md` ("Keeping the pins current", Step
  1.4 minimum-engine note), `README.md`, `justfile.project` pin comment,
  `apply-reminder.yml` idiom comment.
- Release note ✔ — changelog entry carries the migration order: **bump the
  engine pin first, then delete the literal**; deleting first on a pre-#228
  engine hits the hard-error branch.
- ADR-0005 gains a third dated Corrections entry (SSoT now guarded by a test,
  not by uniqueness; justfile still the effective resolver); ADR-0006 notes the
  engine ref now also selects the otterdog version.

## Notes for review

- Pin literal count is unchanged at 5, but all 5 now live in this repo and are
  CI-asserted; downstream mirrors go to zero. `exo-pet/org-config`'s existing
  literal keeps working as a harmless winning override — drop it on its next
  engine-pin bump.
- `template/README.md` names **v1.4.0** as the minimum engine version for
  dropping the literal — an inference (latest tag v1.3.0 + Unreleased has
  `### Added` ⇒ next release is minor). If the next release is cut under a
  different number, that line needs a one-word fix.
- This PR touches `plan.yml`, so the Plan check runs and its empty plan is the
  acceptance evidence, automatically — the #230 fix demonstrating itself.
