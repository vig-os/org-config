# [PR 124](https://github.com/vig-os/org-config/pull/124) chore(config): narrow ORG_CONFIG_CANARY to org-config only (visibility pilot)

Pilot for #123. One secret, chosen because it is the lowest-risk one in the org **and** the only one this repo can migrate declaratively.

## What changes

```jsonnet
orgs.newOrgSecret('ORG_CONFIG_CANARY') {
  selected_repositories+: ['org-config'],
  value: 'pass:org-config/ORG_CONFIG_CANARY',
  visibility: 'selected',
},
```

## Why it is safe

A grep of every `secrets.*` reference across all 14 `vig-os` repos — whole `.github` tree, `.yml` **and** `.yaml`, cross-repo `workflow_call` checked and absent — finds **no workflow anywhere reads `ORG_CONFIG_CANARY`**. It is *written* by `otterdog apply` from the committed SOPS ciphertext and exists only to prove that pipeline (#22). `org-config` is the entire audience. Full matrix: [#123 comment](https://github.com/vig-os/org-config/issues/123#issuecomment-5219672966).

## Why this one is the pilot

The investigation ([#123 comment](https://github.com/vig-os/org-config/issues/123#issuecomment-5219693657)) established that visibility **cannot** be changed without the secret value:

- `PUT /orgs/{org}/actions/secrets/{name}` -> `422 "encrypted_value", "key_id" weren't supplied`
- `PUT .../{name}/repositories` -> `409 cannot update selected repositories ... when the visibility is not set to 'selected'`
- `otterdog apply` **skips** dummy-valued secrets outright (`otterdog/models/secret.py:88`, `include_for_live_patch() == not has_dummy_secret()`), and eleven of the twelve are declared `value: '********'`.

`ORG_CONFIG_CANARY` is the exception: its value is a real credential-provider reference, resolved at apply time by the SOPS-to-`pass` bridge (`apply.yml:243`, gated on `hashFiles('secrets/*.yaml') != ''` — so it runs on *every* apply, not only when `secrets/**` changed). It is therefore not a dummy, `include_for_live_patch` is true, and **apply writes visibility itself**.

That makes this PR a genuine end-to-end proof of the declarative path before the other eleven are attempted by a different mechanism.

## Expected plan

`~ org_secret[name="ORG_CONFIG_CANARY"]` with `visibility = "all" -> "selected"` and the `selected_repositories` addition, plus the permanent allow-listed `vs-dolt` diff. Verified below once the check completes.

## Verification after apply

`gh api orgs/vig-os/actions/secrets/ORG_CONFIG_CANARY` must report `visibility: selected`, and `.../repositories` must list exactly `org-config`. Since nothing consumes the secret there is no consumer workflow to dispatch — the value-preservation question is instead answered for real in the follow-up PR, where a `COMMIT_APP_*` consumer is dispatched after its flip.

Follows #115, #118, #121; part of #123.
