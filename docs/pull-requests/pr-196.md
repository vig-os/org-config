# [PR 196](https://github.com/vig-os/org-config/pull/196) chore(config): drop unsatisfiable approval gate on org-config Main protection

## Description

Drops the structurally unsatisfiable human-review gate on `org-config`'s own `Main protection` ruleset: `required_approving_review_count` 1 → 0 and `requires_code_owner_review` `true` → explicit `false` (with inline rationale, matching devkit's style).

The repo is solo-maintained: an author cannot approve their own PR and every CODEOWNERS rule names that same author, so the gate's only possible outcome was a routine `#OrganizationAdmin` bypass on every merge — the #115 pathology, resolved the same way #167 resolved it on devkit-smoke-test (count-0-with-required-checks). The operative controls are untouched: the required `CI Summary` check, `requires_review_thread_resolution`, the bypass-free `Signed commits` ruleset, and the `production` environment approval that gates every live apply with the plan preview in the same run.

Accepted trade-off, stated plainly: bot-authored PRs (Renovate, release train) were approvable, so count 1 did bind there; at count 0 they may merge on green CI without review. The blast radius is a merged commit, not an applied one. Out of scope: devkit deliberately keeps count 1.
