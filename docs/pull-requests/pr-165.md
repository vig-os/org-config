# [PR 165](https://github.com/vig-os/org-config/pull/165) chore: pre-tag cleanup for v1.1.0 — changelog accuracy, template pin, release recipes

## Summary

Pre-tag cleanup for `v1.1.0`. Makes the `## Unreleased` section true, and fixes
the two code inconsistencies the release-readiness review exposed. No behaviour
change to `drift_layer` or the reusable workflows.

## The finding that changed the plan

The review initially flagged the devkit **1.7.0 / 1.8.0 / 1.9.0** adoptions and
Renovate PRs #160/#161 as *missing* changelog entries. They are not. devkit 1.8.0
retired the per-PR pipeline in favour of **release-time synthesis**
([vig-os/devkit#1423](https://github.com/vig-os/devkit/issues/1423)): every bot PR
since the last stable tag is enumerated at release cut and finalize and rendered
into a `#### Dependencies` block, coalesced to the net delta per dependency.
Hand-writing those entries would have duplicated them.

The real defect was the inverse — the four **hand-written** Renovate entries left
over from the retired pipeline. The synthesizer owns only its own block and never
touches hand-written text, so they would have shipped alongside it, citing
intermediate versions that never appeared in any release. Verified with
`just changelog-preview` (added in this PR):

```text
#### Dependencies

- Update `ruff` from `>=0.6` to `==0.16.2` (#153, #160)
- Update `astral-sh/setup-uv` from `v8.3.2` to `v10.0.0` (#156, #161)
- Lock file maintenance (pip) (#157, #162)
- Adopt vigOS devkit 1.9.0 (#144, #159, #163) — release notes
  ...
```

Against the stale hand-written entries this replaces: `setup-uv ... to v9.0.0`
and `ruff ... to ==0.15.22`.

## Changes

**`docs(changelog)`**
- Remove the four superseded hand-written Renovate entries.
- Record the removal of `renovate-changelog-{build,commit}.yml` under `Removed`,
  including *why* later bot PRs carry no hand-written entry.
- Correct the secret-scanning-extras entry: it claimed the control was recorded
  as **unassertable**, but the shipped `unmanaged-controls.toml` asserts it with
  `expect = "enabled"` / `tolerated = "disabled"` — contradicting the #116 entry
  in the same section. No row in the table uses `kind = "unassertable"`.
- Fix the stale `apply.yml:72-73` citation (moved to `:87` by the #105
  supersession header), in the changelog **and** in the identical citation
  carried in `otterdog/vig-os/vig-os.jsonnet`.
- Drop the empty `### Deprecated` heading and a stray blank line in `### Fixed`.

**`ci(template)`** — `template/.github/workflows/import.yml` was still defaulting
`otterdog_version` to `1.3.4` while the other three template callers moved to
`1.4.0` under #69. A downstream org onboarding from `template/` would import on
one version and plan on another.

**`chore(just)`** — the three devkit release recipes were commented out *and*
dispatched from `dev`, a branch deleted when this repo moved to trunk. Restored
against `main`, plus `changelog-preview` and `promote-release`, which
`docs/DOWNSTREAM_RELEASE.md` already advertises but which never existed (that doc
is devkit-managed, so adding the recipes is the only way to make it true). Tag
prefix and repository are read from `.vig-os` rather than restated.

## Out of scope

`apply.yml`'s `uses: ./.github/workflows/plan.yml` inside a workflow consumed
downstream via `workflow_call`. The guard is `if: inputs.org_github_id == ''`,
but an `if:` gates execution, not reference resolution — same class as #56, which
broke every downstream caller and was caught only by a real `exo-pet` run. Needs a
live downstream apply on the candidate tag, not an edit.
