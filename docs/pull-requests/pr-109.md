# [PR 109](https://github.com/vig-os/org-config/pull/109) refactor: single-source the house repo merge policy and refresh the downstream skeleton

# House repo-defaults overlay + downstream skeleton refresh

Two coupled changes, both feeding `v1.0.1`.

## 1 — House defaults overlay (#108)

The house repository merge policy — merge commits only, `PR_TITLE` / `PR_BODY` —
had **no single source**. It was hand-copied onto individual repo blocks in
`otterdog/vig-os/vig-os.jsonnet` (`allow_merge_commit: true` 12 times, the full
five-field policy 5 times) while the vendored Eclipse base
(`vendor/otterdog-defaults/otterdog-defaults.libsonnet`) declares the exact
opposite, so any newly declared repo silently started on the upstream defaults.
Downstream orgs import the vendor path directly and repeat the overrides
inconsistently.

New `otterdog/vig-os/house-defaults.libsonnet` re-exports the vendored base
template with the policy folded into `newRepo`, and exports three named mixins
(`houseMergePolicy`, `upstreamMergePolicy`, `legacyMergePolicy`) so a repo that
deliberately sits on another policy names it instead of restating five fields.
The `vendor/…` import resolves relative to the overlay, so the same file works
unchanged in this engine repo and beside a downstream org's own vendored tree —
it is org-neutral and copied verbatim, never edited.

`vig-os.jsonnet` now imports the overlay and drops the redundant per-repo merge
fields.

### This is a pure refactor — verified

`jsonnet otterdog/vig-os/vig-os.jsonnet` was captured before and after the
change and the outputs are **byte-identical** (`diff` clean, 1799 lines). No
repo's effective settings move, so `plan` is unchanged.

Keeping that property means the repos that predate the policy carry an explicit
`+ orgs.legacyMergePolicy` (merge commits on, rebase/squash still enabled —
`h5v`, `nvd-mirror`, `qms`, `qx`, `vigos-mvp`, `vs-dolt`), `org-config-testbed`
carries `+ orgs.upstreamMergePolicy` (its whole point is being exactly the
vendored defaults), and `scitadel`/`tessera` keep their deviations, now with a
comment saying so. **Narrowing any of those to the house policy is a live
settings change** — it removes merge buttons contributors may be using — so it is
deliberately out of scope here and belongs to a separate issue.

The overlay was also evaluated in a **simulated downstream layout**
(`otterdog/exo-pet/` with its own `vendor/` tree, no engine files present) to
confirm the relative import and the mixins resolve there too.

## 2 — Downstream skeleton refresh (#106)

`template/` still described the pre-trunk `dev` model retired by #63. A
downstream copying it verbatim got a `plan` caller that never fires (nothing
opens PRs against `dev`), an `apply` caller that never fires (nothing pushes to
`dev`), a Renovate base pattern matching no branch, and a runbook pointing at a
branch that does not exist — silent no-ops, the worst failure mode for a
write-path workflow. All eight references are now `main`, and the example engine
pins in `plan.yml` are bumped to `v1.0.1`.

The skeleton also ships the overlay at
`template/otterdog/YOUR_ORG/house-defaults.libsonnet`, with
`template/otterdog/README.md` and the onboarding runbook documenting the one-line
import change and how to normalize an `otterdog import` against it.

## Downstream adoption (two steps)

1. Copy `otterdog/vig-os/house-defaults.libsonnet` (verbatim, no edits) to
   `otterdog/<org>/house-defaults.libsonnet` — beside the existing `<org>.jsonnet`
   and `vendor/` tree.
2. In `<org>.jsonnet`, change
   `local orgs = import 'vendor/otterdog-defaults/otterdog-defaults.libsonnet';`
   to `local orgs = import 'house-defaults.libsonnet';`, then delete every repo's
   now-redundant house merge fields — and add `+ orgs.legacyMergePolicy` (or
   `+ orgs.upstreamMergePolicy`) to any repo that is not on the house policy, so
   its plan stays empty.

## Verification

- `jsonnet` eval of `otterdog/vig-os/vig-os.jsonnet`: identical before/after.
- Simulated downstream layout evaluates and resolves the mixins.
- `just precommit` green (includes `otterdog validate --local`: 0 errors) and
  `just test` green (43 passed). The declared repo set is unchanged — every
  `orgs.newRepo('<name>')` literal is preserved, which is what the inventory
  sweep's extraction is anchored on.
