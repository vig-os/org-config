# [PR 301](https://github.com/vig-os/org-config/pull/301) chore(config): put scitadel, qx and tessera on ADR-0008 tier A

## Description

PRs 4, 5 and 6 of the #294 plan in one PR. This puts `scitadel`, `qx` and `tessera` on [ADR-0008](docs/adr/0008-repository-protection-and-merge-policy.md) tier A. Every ruleset was decided after checking every writer on the live repo: default-branch and `dev` workflows, the Apps and tokens they mint, release tooling, recent run actors, tags, and commit signatures on `main`, `dev` and open PR branches.

The rendered config differs from `main` only in the three repo blocks. Org-level settings and every other repo are byte-identical.

## Merge / apply order (required)

1. **vig-os/qx#311 merges first** (closes vig-os/qx#310). It adds the `CI Summary` job this PR requires on qx `main`. Applied the other way round, qx's `Main protection` would require a context no PR reports, and every qx merge would need an org-owner bypass.
2. Then this PR merges, and the apply runs.
3. **Right after the apply, by hand**, because `apply.yml` runs without `--delete-resources` and never deletes:
   - `scitadel` → Settings → Rules → Rulesets: delete `main protection` and `dev protection` (lower-case). Otterdog keys rulesets by exact name, so the rename plans as *add the new ruleset + remove the old one*. Only the add is applied. If GitHub refuses the new name because of a case-insensitive clash with the old one, the apply goes red on those two adds. In that case delete the two old rulesets first and re-run the apply.
   - `tessera` → Settings → Branches: delete the classic branch protection rules on `dev` and `main`.

No scitadel or tessera PR is needed. The only bot writing directly to a protected branch in either repo is the Commit App syncing issues to `dev`, and it gets a `Dev protection` bypass, as on commit-action. Nothing writes to `main` directly.

### ADR-0008 exceptions

- **Added**: `qx` and `tessera` Tag protection bypass is `#OrganizationAdmin` (always), not a release App, because tags are pushed by hand. `tessera` has no `Signed commits`, because its contributor's commits are unsigned. `tessera` keeps `dev` as its default branch.
- **Removed**: the three transitional rows (scitadel squash/unpinned, qx no rulesets, tessera classic/all-three/no-delete).

### tessera default branch: kept on `dev`

The jsonnet said to flip at the first alpha, and #294's plan says "back to `main`". Tessera's actual state says not yet:

- `dev` is 11 commits ahead of `main`, and every PR, Dependabot and release-plz target it. #436 made release-plz run on every push to `dev` *after* the alpha.
- `main` lacks the devkit scaffold and `devkit-upgrade.yml`, and its `sync-issues.yml` still mints the repo-scoped sync App.

Scheduled workflows run from the default branch, so a flip would switch them to those stale copies. The exit condition is recorded in the ADR and the jsonnet: `main` carries the scaffold, or tessera#441 decides the release train.

## Surprises

- **scitadel's squash-only policy was incompatible with its own release train.** `promote-release` merges with `gh pr merge --merge`, yet #222 (0.8.0, 2026-09-24) landed as a two-parent merge commit. So merge commits were on live at that moment, and the declared `allow_merge_commit: false` has since been re-applied: live is now squash-only again. Left as it was, the next scitadel promote would fail.
- **Required-check coverage on scitadel narrows.** `CI Summary` aggregates `ci.yml` only (lint via pre-commit with `cargo fmt`, `cargo test` on Linux, commit messages, scaffold drift, dependency review). `rust-ci.yml`'s `clippy -D warnings` and `Test (macos-latest)` no longer gate merges. This follows the ADR's one-aggregator rule. If they should keep gating, the fix belongs in scitadel: fold them into `CI Summary`'s `needs`, or add clippy to pre-commit.
- **tessera's main contributor pushes unsigned commits**, while the same contributor's scitadel and qx commits are signed. That points to a local config gap on tessera.

Two checks otterdog makes and `plan` does not, run with the token this run minted: `apply` writes every App-shaped actor by resolving its slug through `GET /apps/{slug}`, and otterdog's read path maps a live App actor back to a slug only through `GET /orgs/{org}/installations`.
