# [PR 297](https://github.com/vig-os/org-config/pull/297) chore(config): drop scitadel's retired release-please credentials

## Description

Closes #295. Drops `scitadel`'s three retired release-please credentials from its `orgs.newRepo('scitadel')` block in `otterdog/vig-os/vig-os.jsonnet`; `CARGO_REGISTRY_TOKEN` is kept.

The "nothing references them" claim was re-verified independently on 2026-09-28 against the **live trees** (API tarballs of `main` @ `0afad20` and `dev` @ `582c4a6`, not the code-search index): the only hits for `RELEASE_BOT_PRIVATE_KEY` / `RELEASE_PLEASE_TOKEN` / `RELEASE_BOT_APP_ID` / `3931309` are `docs/RELEASING.md` (which calls them deletable). All `secrets.RELEASE_*` reads in workflows are the org-level `RELEASE_APP_CLIENT_ID` / `RELEASE_APP_PRIVATE_KEY`. The seven stale feature branches (last touched 2026-02/03) carry no `release-please.yml` and no reference either.

## Changes Made

- `otterdog/vig-os/vig-os.jsonnet` (`scitadel`): removed `orgs.newRepoSecret('RELEASE_BOT_PRIVATE_KEY')`, `orgs.newRepoSecret('RELEASE_PLEASE_TOKEN')`, and the `variables:` array whose only entry was `orgs.newRepoVariable('RELEASE_BOT_APP_ID')` (`3931309`). The empty array is dropped, matching every other repo block that declares no variables.
- `CHANGELOG.md`: entry under `## Unreleased` › `### Removed`.

## Changelog Entry

### Removed

- **`scitadel`'s retired release-please credentials** ([#295](https://github.com/vig-os/org-config/issues/295)): the `RELEASE_BOT_PRIVATE_KEY` and `RELEASE_PLEASE_TOKEN` repo secrets and the `RELEASE_BOT_APP_ID` repo variable (plaintext `3931309`, the `vig-os-release-please` App) are dropped from the `scitadel` block of `otterdog/vig-os/vig-os.jsonnet`, and the now-empty `variables:` array goes with them, matching every other repo block that declares none. `scitadel` retired release-please in [vig-os/scitadel#207](https://github.com/vig-os/scitadel/issues/207) (shipped in 0.8.0) and releases on the devkit train, which authenticates with the org-level `RELEASE_APP_CLIENT_ID` / `RELEASE_APP_PRIVATE_KEY` pair. Re-confirmed on 2026-09-28 against the **live trees rather than the code-search index**: the full `main` and `dev` trees of `vig-os/scitadel` name none of the three outside `docs/RELEASING.md`, which already calls them deletable, and none of the seven stale feature branches carries a `release-please.yml` or a reference either — so the [#112](https://github.com/vig-os/org-config/issues/112) rule that no numeric `*_APP_ID` is deleted while a pinned workflow still reads it is satisfied rather than waived. `CARGO_REGISTRY_TOKEN` stays deliberately: trusted publishing is `scitadel`'s primary crates.io path, but `publish-crates.yml` keeps the token as its explicit fallback. Because `otterdog apply` never deletes secrets or variables, the live values on `vig-os/scitadel` are deleted out-of-band after merge; until then the plan shows them as pending deletions. The `vig-os-release-please` App itself is still installed on the org and is untouched here.
